# 02 · 数据库设计

数据库文件：`echoloop.db`，版本 1，使用 sqflite。
建表语句集中在 `lib/data/db/database_schema.dart`，一处修改全局生效。

外键约束已开启（`PRAGMA foreign_keys = ON`），删除媒体时字幕与收藏会级联清理。

---

## 1. 表关系

```
                ┌──────────────┐
                │    media     │  媒体库条目（只存 URI 引用）
                └──┬───┬───┬───┘
                   │   │   │
      1:N          │   │   │          1:N
   ┌───────────────┘   │   └────────────────┐
   ▼                   │ 1:N                ▼
┌──────────────────┐   │          ┌──────────────────┐
│ subtitle_track   │   │          │   loop_preset    │
│ 字幕轨（可多条）  │◀──┘          │   片段收藏        │
└────────┬─────────┘              └──────────────────┘
         │ 1:N
         ▼
┌──────────────────┐      ┌──────────────────┐
│    subtitle      │      │     settings     │  全局配置（key-value）
│  字幕单句（毫秒） │      └──────────────────┘
└──────────────────┘
```

## 2. media · 媒体库

一条记录代表「用户导入过的一个音视频文件」。**只存 URI 引用，不复制文件**。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增主键 |
| `uri` | TEXT NOT NULL UNIQUE | 文件引用。`content://` 或 `file://`。唯一约束用于导入去重 |
| `name` | TEXT NOT NULL | 显示名，可被「重命名」修改，不影响原文件 |
| `kind` | TEXT NOT NULL | `video` 或 `audio`，决定播放页是否渲染画面区域 |
| `mime_type` | TEXT | 系统给的 MIME，部分机型为空，此时靠扩展名判断 |
| `duration_ms` | INTEGER | 时长。导入时取自系统元数据解析器，播放后会用内核回报的值校正 |
| `size_bytes` | INTEGER | 文件体积，列表页展示 |
| `thumbnail_path` | TEXT | 视频首帧缩略图的本地缓存路径。抽帧失败为 NULL，界面退化成图标 |
| `last_played_at` | INTEGER | 最近播放时间（epoch 毫秒）。媒体库按它倒序排，从未播过的排最后 |
| `position_ms` | INTEGER | 上次播放位置，下次进入续播 |
| `loop_start_ms` | INTEGER | **补充字段**：该文件的 A 点 |
| `loop_end_ms` | INTEGER | **补充字段**：该文件的 B 点 |
| `loop_mode` | TEXT NOT NULL | **补充字段**：`off` / `infinite` / `count` |
| `loop_count` | INTEGER NOT NULL | **补充字段**：指定遍数模式下的遍数 |
| `created_at` | INTEGER NOT NULL | 导入时间，同为 NULL 播放时间时的次级排序键 |

### 补充字段的由来

需求第 5 节给出的 `media` 字段清单里没有循环区间，但第 4.2 节明确要求
「循环区间为单文件独立存储，切换文件时清空当前循环状态（重新打开该文件时恢复）」。
要满足这条规则就必须有落点，因此在 `media` 上补了 4 个字段，
而不是塞进 `settings` 表拼字符串键。放在同一行还有个好处：
切换文件只是一次查询，不用额外查配置。

### 两个使用约定

- 播到文件末尾时，`position_ms` 会被归零。否则下次打开一个已播完的文件会一进来就停在末尾。
- 删除媒体库条目只删这一行（以及级联的字幕与收藏），
  `thumbnail_path` 指向的缓存文件由服务层顺手删掉，**手机上的原文件完全不动**。

## 3. subtitle_track · 字幕轨

一个媒体可以挂多条字幕轨，对应「中英双语同时显示」这条需求。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增主键 |
| `media_id` | INTEGER NOT NULL | 外键，级联删除 |
| `name` | TEXT NOT NULL | 轨道名，如「导入的字幕」「我的手写字幕」 |
| `language` | TEXT | 语言标签，预留字段，当前界面不做选择 |
| `source` | TEXT NOT NULL | `imported` 手动导入 / `manual` 手动编辑 / `ai` AI 识别 |
| `is_active` | INTEGER NOT NULL | **补充字段**：是否正在显示 |
| `created_at` | INTEGER NOT NULL | 创建时间，也是轨道排序依据 |

### is_active 的设计

需求第 4.3 节要求「可切换显示哪一条，也可同时显示」。
这里用一个布尔标记表达激活状态，于是：

- **单语模式**：把目标轨设为 1，其余全部置 0（`setExclusiveActive`）
- **双语模式**：两条轨都置 1，播放页会把它们的字幕句按时间合并渲染

用一个字段覆盖两种用法，比再加一张关联表轻得多。

## 4. subtitle · 字幕单句

字幕的最小单位。时间一律用**毫秒整数**，与需求里「字幕表设计为通用结构」一致。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增主键 |
| `media_id` | INTEGER NOT NULL | 外键，级联删除。冗余一份是为了按媒体直接查，不用先查轨 |
| `track_id` | INTEGER NOT NULL | 外键，级联删除 |
| `line_index` | INTEGER NOT NULL | 轨内序号，从 0 开始。界面显示时加 1 |
| `start_ms` | INTEGER NOT NULL | 起始时间（毫秒） |
| `end_ms` | INTEGER NOT NULL | 结束时间（毫秒） |
| `text` | TEXT NOT NULL | 文本，多行用换行符连接 |
| `source` | TEXT NOT NULL | 同轨道，保留单句级别的来源标识 |

### 为什么字幕表与轨道表分开

需求明确要求两张表。分开的实际收益是：换字幕（比如中英切换）不用动数据，
只改 `is_active`；AI 识别追加一条新轨，也不会污染已有字幕。

### 索引

```sql
CREATE INDEX idx_subtitle_track ON subtitle (track_id, start_ms);
CREATE INDEX idx_subtitle_media ON subtitle (media_id, start_ms);
```

高频查询只有两种：按轨读全部字幕（播放页与编辑器），
以及按媒体读激活轨字幕（播放页高亮、吸附、双语合并）。
两个索引正好覆盖，且都带 `start_ms` 保证结果天然有序，不需要额外排序。

## 5. loop_preset · 片段收藏

把调好的 AB 片段存下来，下次一键载入。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 自增主键 |
| `media_id` | INTEGER NOT NULL | 外键，级联删除 |
| `start_ms` | INTEGER NOT NULL | 片段起点 |
| `end_ms` | INTEGER NOT NULL | 片段终点 |
| `note` | TEXT NOT NULL | 备注。留空时自动生成 `1:23.4 → 1:28.0` 这样的时间标注 |
| `created_at` | INTEGER NOT NULL | 创建时间，倒序排列 |

界面入口在播放页的循环设置面板里：轻点载入，长按删除。

## 6. settings · 配置项

key-value 结构，整表读出来交给 `AppSettings.fromValues()` 组装。
好处是加一个设置项不用改表结构，也不用多写一次查询。

| 键 | 类型 | 默认值 | 对应设置 |
| --- | --- | --- | --- |
| `playback.speed` | double | 1.0 | 全局倍速，切换文件后保持 |
| `playback.gap_seconds` | int | 0 | 跟读停顿秒数，0 表示关闭 |
| `playback.loop_mode` | string | infinite | 手动框选时默认使用的循环模式 |
| `playback.loop_count` | int | 3 | 指定遍数模式的默认遍数 |
| `subtitle.snap_to_boundary` | 0/1 | 1 | AB 边界是否自动吸附字幕 |
| `subtitle.visible` | 0/1 | 1 | 播放页是否显示字幕列表 |
| `shadowing.record_during_gap` | 0/1 | 0 | 停顿期间是否自动录音 |
| `ui.theme_mode` | string | system | 跟随系统 / 浅色 / 深色 |
| `library.last_media_id` | int | 无 | 上次打开的媒体，用于后续做「继续上次」 |

读取时所有键都用 `tryParse` 加默认值兜底：某个键缺失或被写坏，
只会退回默认值，不会让应用起不来。

## 7. 迁移策略

当前版本为 1，`onUpgrade` 是空实现，但注释里写明了原则：

> 后续加字段时按 `oldVersion` 逐级迁移，**不做 drop 重建**。

原因很直接：用户已经导入了媒体、调好了循环区间、录了字幕，
drop 重建意味着这些全部清零。加字段只需要 `ALTER TABLE ADD COLUMN` 一条语句，
成本远低于让用户重新导入一遍。
